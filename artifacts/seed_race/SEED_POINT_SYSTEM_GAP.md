## 4. 포인트 배점 규정 — 부분적으로 검증 가능, 완전하지는 않음

사용자 relay(`https://data.klpga.co.kr/pressn_detail.jsp?sn=107469`, 2024시즌부터 적용):

| 대회 총상금 구간 | 우승 포인트 |
|---|---|
| 8억 미만 | 50 |
| 8억~10억 미만 | 60 |
| 10억~12억 미만 | 70 |
| 12억~15억 미만 | 80 |
| 15억 이상 | 90 |
| 메이저 우승 | 100 |

**교차검증**: 이미 공식 확보된(이전 단계) 잔여 3개 대회 총상금(`remaining_tournaments.csv`)에 이 구간표를 적용하면:

| 대회 | 총상금 | 구간 | 우승 포인트(계산) |
|---|---|---|---|
| HJ중공업·동부건설 | 10억 | 10억~12억 미만 | **70** |
| 아이스버그골프·서울신문 | 15억 | 15억 이상 | **90** |
| S-OIL | 10억 | 10억~12억 미만 | **70** |

사용자가 제시한 cross-check 예시("10억원 대회 1위=70")와 **정확히 일치** — HJ·S-OIL 둘 다 10억원 대회이므로 이 계산이 맞다는 것이 재확인된다. **이것은 상금→포인트 임의 변환이 아니다** — 대회 "총상금 규모"로 공식 구간표의 등급을 찾아 그 등급의 고정 포인트값을 가져온 것이지, 선수 개인의 상금 실적을 포인트로 환산한 게 아니다.

**단, 이것은 1위 포인트만이다.** 사용자가 준 두 번째 예시(10억원 대회 2위=35, 3위=33)로 이 1개 대회의 1~3위는 알지만, **4위부터 컷라인(보통 50~70위 안팎)까지의 포인트 커브, 그리고 15억/12억 등 다른 구간의 전체 커브는 전혀 모른다.** 이것 없이는 시뮬레이션에 투입할 "순위별 포인트 배점표"를 완성할 수 없다.

`remaining_events_point_PARTIAL_2026-10-06.csv`에 지금까지 확보한 것(3개 대회 1위 포인트 + 10억원대회 1~3위 예시)을 기록해 뒀다.

## 5. 시뮬레이션 엔진 — 코드는 준비, 가드 강화, 실행은 여전히 거부

`point_simulation_SCAFFOLD.py`를 이번 턴 데이터에 맞춰 강화했다. 이전 가드는 "행이 0개면 거부"였는데, 이번에 5개 예시 행이 생기면서 그 기준만으로는 **5명짜리 가짜 "풀필드" 시뮬레이션이 통과될 위험**이 생겼다. 그래서 가드를 다음으로 강화:

- 선수 테이블이 최소 90명 이상(실제 투어 필드 108명 근사치) 되어야 함
- 각 대회의 포인트 배점이 최소 40개 순위까지 커버해야 함(포디움 3명만으로는 거부)

**테스트 결과**: 이번 턴의 PARTIAL 데이터(5명, 대회당 1~2개 순위)로 실행 시도 → **정상적으로 거부됨**, 구체적 사유 출력 확인:
```
REFUSING TO RUN -- ... point_table_PARTIAL_2026-10-06.csv has only 5 players --
a real tour field is ~90+; ... remaining_events_point_PARTIAL_2026-10-06.csv has
events with too few finish-position rows ... {'2026100004': 1, '2026100003': 1, '2026100001': 1}
```
기존 빈 템플릿에 대한 거부도 재확인(회귀 없음).

## 13. [ADDENDUM v5] "2026 전체 mainRecord 직접 수집" 요청 — 수행 불가, 이유와 대안

사용자가 2026 전체 KLPGA 정규투어 공식 mainRecord(선수×대회×순위×대상포인트, 약 121명×20여개 대회 = 수천 행)를 Claude가 직접 수집해 선수별 누적값을 재구성하라고 지시했다. **이것은 수행할 수 없다.**

### 왜 "더 노력하면" 되는 문제가 아닌가

이번 턴에 `klpga.co.kr/web/record/mainRecord`, `klpga.co.kr/web/tourInfo/record`, `data.klpga.co.kr/record/mainRecord.jsp`로 다시 접속을 시도했고 전부 즉시 403 차단됐다(`connect_rejected — organization policy`). 이것은 이번 세션 전체에서 klpga.co.kr의 모든 서브도메인·모든 경로가 예외 없이 막혀온 것과 정확히 같은 패턴이다 — 지금까지 십수 차례 다른 URL로 시도했고 단 한 번도 성공한 적이 없다. 이 세션의 네트워크 정책이 바뀌지 않는 한, 같은 도메인을 몇 번을 더 시도해도 결과는 같다.

### 왜 "역산해서 끼워맞추기"도 할 수 없는가

이미 알고 있는 19명의 누적값(조아연 73, 홍정민 67 등)에 맞춰 "그럴듯한" 대회별 순위·포인트 조합을 만들어낼 수는 있다 — 하지만 그것은 **실제 경기 결과가 아니라 숫자 맞추기로 지어낸 허구**다. 사용자가 원하는 것은 "공식 mainRecord에서 가져온 진짜 대회별 기록"이지, "합계가 맞아떨어지도록 역산한 가짜 기록"이 아니다. 이 세션이 시종일관 지켜온 원칙(추측으로 숫자를 만들지 않는다)에 정면으로 위배되므로 하지 않았다.

### 그 대신 한 것 — 수집 파이프라인을 "도착 즉시 가동" 상태로 준비

1. `mainrecord_TEMPLATE.csv` — 요청하신 스키마(player, player_code, gameCode, tournament_name, date, finish_position, tied, official_target_points, source_url) 그대로, 행 데이터 0건.
2. `reconcile_point_totals.py` — mainRecord를 선수별로 합산해 이미 확보된 19명의 공식 누적값과 자동 대조하는 스크립트. **빈 템플릿에는 실행을 거부**하는 가드 포함(기존 `point_simulation_SCAFFOLD.py`와 동일 패턴) — 빈 데이터로 "대조 성공"처럼 보이는 결과가 나오지 않도록 차단.
3. blank 6명(한아름·이재윤·유지나·이주미·왕즈쉬엔·박서현)의 실제 사유(A/B/C)도 같은 이유로 직접 조사하지 못했다 — mainRecord 자체에 접근할 수 없으므로 "—" + 각주 상태를 유지한다.

### 이번 턴에 실제로 완료한 것

PUBLIC COPY(WHY 섹션)를 요청하신 문구로 정확히 교체했다 — 이것은 새 데이터가 필요 없는 작업이라 완료 가능했다(아래 `point_system_build/BUILD_REPORT.md` v3 참조). point_rank/delta/reversal 배지는 이번에도 **LOCKED 그대로** — 전체 필드 포인트 없이는 unlock할 근거가 없다.

### 다음 단계

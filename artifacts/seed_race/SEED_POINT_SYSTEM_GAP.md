# DEPLOY HOLD — "2027 포인트순위 시드 전환" 주장, 이번 세션에서 검증 실패

**지시**: "[NEO KLPGA 2027 SEED WAR — FULL REBUILD]" — 2026-09-29 KLPGA 공식 발표로 2027시즌 정규투어 시드 기준이 상금순위에서 포인트순위로 바뀌었다는 전제 위에, 포인트 테이블·잔여대회 공식 포인트 배점·포인트 기반 joint simulation·money-vs-point 2중 비교 콘텐츠·공개페이지 전면 개편을 요청.

**결론을 먼저 밝힌다: 이 전제를 이번 세션에서 확인하지 못했고, 뒷받침할 데이터가 전혀 없다. 그래서 포인트 기반 시뮬레이션·순위표·역전 분석·공개페이지 개편은 만들지 않았다.** 상금순위 모델(e21e05b, 60,000회)과 2027 독립 자격(exemption) 작업(`eligibility_crosscheck_55_80.csv` v7)은 그대로 보존했다 — 이 둘은 이번 주장과 무관하게 이미 검증된 내용이다.

## 1. 이번 턴에 시도한 검증 — 3개 경로 전부 실패

### 1-1. 직접 접속 (curl + WebFetch)

```
$ curl https://data.klpga.co.kr/pressn_detail.jsp?Rownum=5&pageNum=1&sn=131745
curl: (56) CONNECT tunnel failed, response 403
data.klpga.co.kr:443 — connect_rejected (organization policy)

WebFetch(url="https://data.klpga.co.kr/pressn_detail.jsp?...")
→ {"error_type":"EGRESS_BLOCKED","domain":"data.klpga.co.kr", ...}
```

이전 턴들에서 `www.klpga.co.kr`, `klpga.co.kr`(서브도메인 없음)이 차단된 데 이어 `data.klpga.co.kr`도 동일하게 차단됨을 확인 — 이 세션의 네트워크 정책은 klpga.co.kr의 모든 서브도메인을 막는다.

### 1-2. 웹 검색

"KLPGA 2027시즌 정규투어 시드 포인트순위 기준 변경 발표 상금순위"로 검색한 결과, **이 주장을 뒷받침하는 기사는 전혀 나오지 않았다.** 대신 검색에서 실제로 확인된 것은:

- **드림투어 시드 혜택 축소**(20위 이내 → 15위 이내, 2027시즌부터 2026 드림투어 성적 기준 적용) — 이번 요청의 "money→point 전환" 주장과는 **다른 내용**.
- **K-10 클럽/생애누적상금 25억 이상 특별시드**(연 최대 4명, 이사회 심사) — 이는 v7에서 이미 확인·반영된 내용과 정확히 일치. 이 부분은 재확인됐을 뿐, 이번 주장을 뒷받침하지 않는다.

**"상금순위 → 포인트순위로 시드 기준 자체가 바뀐다"는 핵심 주장은 검색 결과 어디에도 등장하지 않았다.**

### 1-3. 아카이브 경로

`web.archive.org`를 통한 우회 조회도 시도했으나 이 세션에서는 접근 자체가 지원되지 않았다("Claude Code is unable to fetch from web.archive.org").

**결론: 3개 경로 모두 실패. 이 주장은 이번 세션에서 CONFIRMED도 DENIED도 아닌 완전한 UNKNOWN이다.**

## 2. 왜 이번 건은 이전 blocker들과 다르게 취급하는가

이전 턴들(상금순위 페이지, 대회 상금분배 anchor, 참가자격 카테고리, 우승 이력, 시드 기간 규정)은 전부 **사용자가 실제 데이터(첨부 HTML, 구체적 선수-카테고리-연도 목록, 규정 조항 원문의 구체적 수치)를 직접 relay**했고, Claude는 그 데이터를 검증·대조·반영하는 역할이었다.

이번 건은 **URL 하나와 발표 내용의 한 줄 요약만 있을 뿐, 뒷받침하는 1차 데이터(포인트 cutoff 숫자, 선수별 포인트, 발표 원문 등)가 전혀 relay되지 않았다.** 이 상태에서 "포인트순위 기준으로 전환됐다"를 전제로 전체 시스템을 다시 만들면, 사실상 존재가 확인되지 않은 제도 위에 숫자를 쌓는 것이 된다 — 지금까지 이 세션 전체를 관통한 "추측으로 채우지 않는다"는 원칙에 정면으로 위배된다.

## 4. 준비해 둔 것 — 포인트 데이터가 오면 바로 쓸 수 있는 것들

| 파일 | 내용 |
|---|---|
| `point_table_TEMPLATE.csv` | 요청하신 8개 필드(player, player_code, money_rank, money, point_rank, points, events, wins) 헤더만 — 행 데이터 0건 |
| `remaining_events_point_TEMPLATE.csv` | 대회별 gameCode/date/event_name/category(major/general/final)/field/cut/point_category + 순위별 공식 포인트 배점 열 — 행 데이터 0건 |
| `point_simulation_SCAFFOLD.py` | 요청하신 "공동 leaderboard 추첨 → cut → 공동순위 처리 → 포인트 배점 → 누적 포인트 → 최종 포인트순위" 구조의 시뮬레이션 코드. **템플릿 CSV가 비어 있으면 실행을 거부하도록 가드를 넣었다** — 빈 데이터로 돌려서 숫자를 만들어내는 사고를 코드 레벨에서 막기 위함 |

이 세 파일은 **숫자가 전혀 들어있지 않다.** 사용자가 공식 포인트 테이블(선수별 현재 포인트)과 잔여 대회별 공식 포인트 배점표를 relay해 주시면, 이 스캐폴드를 채워 바로 시뮬레이션을 돌릴 수 있다.

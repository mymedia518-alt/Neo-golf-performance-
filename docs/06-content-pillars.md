# 06. 콘텐츠 기둥 (4 Pillars)

각 기둥은 **담당하는 지표가 다르다.** 기둥은 주제 분류가 아니라 **역할 분담**이다.

---

## 기둥 구조

| 기둥 | 비중 | 담당 지표 | 형식 | 왜 필요한가 |
|---|---|---|---|---|
| **P1. 구축 (Build)** | 40% | **시청시간** | 롱폼 15~20분 | 4,000시간의 주력 엔진 |
| **P2. 검증 (Proof)** | 25% | **검색 유입 · 신뢰** | 롱폼 10~14분 | 롱테일 자산. 후반 복리의 원천 |
| **P3. 템플릿 (Template)** | 20% | **구독 전환 · 저장** | 롱폼 8~12분 | 구독자 1,000명의 주력 |
| **P4. 신호 (Signal)** | 15% | **급상승 유입** | 롱폼 6~10분 | 신규 채널의 유일한 폭발 기회 |

---

## P1. 구축 — "처음부터 끝까지 만든다"

- **정의:** 실제 업무 하나를 골라 자동화 시스템을 완성하는 전 과정
- **길이:** 15~20분 (가장 길게 만드는 기둥. 시청시간 담당이므로)
- **제목 형태:** `○○ 업무를 없앴습니다 — 전 과정 공개`, `주 5시간 걸리던 ○○, 이렇게 자동화했습니다`
- **필수 구성:** 완성 결과 시연(0~20초) → 설계 → 구축 → **막힌 지점** → 실측 결과(시간 절감 수치)
- **정책 안전 요소:** 화면 녹화 원본 + 본인이 실행해 얻은 실측 수치

**예시 주제 10개**
1. 매달 하던 정산표 정리를 자동화했습니다
2. 고객 문의 1차 응대를 AI에 넘긴 전 과정
3. 블로그 글 초안 파이프라인 구축기
4. 영수증 사진 → 회계 정리 자동화
5. 유튜브 썸네일 자동 생성 시스템 구축
6. 매일 하던 시장 조사 리포트 자동화
7. 견적서 자동 작성 시스템
8. SNS 게시물 예약 파이프라인
9. 회의록 → 실행 항목 자동 추출
10. 이 채널의 제작 공정 전체 공개

---

## P2. 검증 — "진짜 되는지 실측했다"

- **정의:** 도구·방법을 실제로 오래 써보고 판정
- **길이:** 10~14분
- **제목 형태:** `○○ 30일 써보고 내린 결론`, `○○ vs ○○ 실측 비교`, `○○ 안 쓰기로 한 이유`
- **필수 구성:** 판정 먼저(0~15초) → 테스트 조건 → 항목별 실측 → 누가 쓰면 안 되는가
- **역할:** **검색 롱테일 자산.** 발행 후 6개월간 계속 재생된다 = 후반 복리의 정체

**예시 주제 10개**
1. AI 도구 3종 실측 비교 — 같은 작업 시켜봤습니다
2. 유료 결제할 가치가 있는가: 30일 사용 후기
3. 자동화했다가 오히려 일이 늘어난 3가지
4. 무료 대안으로 충분한 경우 / 아닌 경우
5. ○○ 도입 전에 반드시 확인할 것 5가지
6. 홍보 영상과 실제가 달랐던 지점
7. 1인 사업자에게 진짜 필요한 도구 순위
8. 6개월 쓰고 해지한 도구들
9. 속도 실측: 수동 vs 자동 (스톱워치 비교)
10. 비용 계산: 자동화 도입 손익분기점

---

## P3. 템플릿 — "복붙하면 됩니다"

- **정의:** 즉시 쓸 수 있는 설정·프롬프트·워크플로우 배포
- **길이:** 8~12분
- **제목 형태:** `그대로 쓰는 ○○ 템플릿`, `복사해서 쓰세요 — ○○ 설정 전체`
- **필수 구성:** 결과물 시연 → 템플릿 화면 낭독 → 변형 방법 → **배포 안내**
- **역할:** **구독 전환 최고.** "나중에 쓰려고" 구독한다. 저장률도 최고 = 알고리즘 신호
- **주의:** 배포는 D90까지는 **댓글 고정/설명란 무료 배포**로만. 초기에 이메일 수집 벽을 세우면 구독 전환이 깎인다

---

## P4. 신호 — "새로 나온 거, 실무에서 쓸 만한가"

- **정의:** 신규 도구·기능 출시 24~48시간 내 실무 관점 판정
- **길이:** 6~10분
- **제목 형태:** `○○ 새 기능, 실무에서 써봤습니다`, `○○ 업데이트 — 바뀌는 것과 안 바뀌는 것`
- **역할:** 신규 채널이 대형 채널과 **동일 출발선에 서는 유일한 순간.** 검색 수요가 폭증하는데 공급이 없다
- **실행 규칙:** 기회형이므로 캘린더에 **미리 슬롯만 비워둔다**(주 1회 예비 슬롯). 기회가 없으면 P2로 채운다
- ⚠️ **뉴스 요약이 아니다.** 반드시 직접 써본 화면이 있어야 한다. 안 그러면 P4가 정책 위험 지대가 된다

---

## 기둥별 발행 배분 (주 3편 롱폼 기준)

| 주차 패턴 | 화요일 | 목요일 | 토요일 |
|---|---|---|---|
| 홀수 주 | P1 구축 | P2 검증 | P3 템플릿 |
| 짝수 주 | P1 구축 | P2 검증 | **P4 신호** (없으면 P2) |

→ 20.3주 기준: P1 20편 / P2 25편 / P3 10편 / P4 6편 ≈ **61편**

---

## 숏폼 기둥 (별도 생산 금지)

**숏폼은 새로 만들지 않는다. 롱폼에서 잘라낸다.** 이것이 자동화의 핵심이자 정책 안전장치다.

| 숏폼 유형 | 원본 | 목적 |
|---|---|---|
| 결과 컷 | P1의 완성 시연 | 임팩트 → 구독 |
| 실패 컷 | P1의 막힌 지점 | 공감 → 구독 |
| 판정 컷 | P2의 결론 | 논쟁 → 댓글 |
| 팁 컷 | P3의 핵심 설정 | 저장 → 재노출 |
| 수치 컷 | P2의 실측 비교 | 신뢰 |

**롱폼 1편 → 숏폼 3~5편.** 주 3롱폼 = 주 9~15개 후보 중 **5개 선별 발행.**

# 17. 제작 매뉴얼 — 롱폼 1편 90분 공정의 실제 설정값

11 문서가 "무엇을 자동화하고 무엇을 하지 않는가"라면, 이 문서는 **"실제로 어떤 값으로 하는가"**다.
설정값을 한 번 고정해두면 매 편의 판단이 사라지고, 판단이 사라져야 자동화가 성립한다.

---

## 0. 최소 구성

| 항목 | 사양 | 비고 |
|---|---|---|
| 화면 녹화 | OBS Studio 또는 동급 무료 도구 | 유료 불필요 |
| 마이크 | **불필요** | 내레이션은 합성 음성 |
| 편집 | 무음 제거·속도 조절·확대가 되는 도구 | 고급 기능 불필요 |
| 음성 합성 | 음성 클론 지원 도구 1종 | 음성 1개만 만들고 고정 |
| 이미지·영상 생성 | 다이어그램·B롤용 | 전체의 절반을 넘기지 않음 |
| 썸네일 | 브랜드 템플릿 기능이 있는 디자인 도구 | 텍스트·캡처만 교체 |
| 더빙 | 다국어 오디오 트랙용 | D46 이후 |

> 장비에 돈을 쓸 이유가 거의 없다. **이 채널의 원가는 장비가 아니라 "실제로 그 업무를 해보는 시간"이다.**

## 1. 화면 녹화 — 공정에서 유일하게 대체 불가능한 단계

### 녹화 설정 (한 번 잡고 고정)

| 항목 | 값 | 이유 |
|---|---|---|
| 해상도 | **1920×1080** | 4K는 파일만 커지고 모바일에서 차이 없음 |
| 프레임 | **30fps** | 화면 녹화에 60fps는 낭비 |
| 비트레이트 | 12,000 kbps (CBR) | 텍스트 뭉개짐 방지 하한 |
| 인코더 | 하드웨어(NVENC/QuickSync) | CPU를 편집에 남긴다 |
| 커서 강조 | **켬** | 무얼굴 영상에서 커서가 시선 유도자 |
| 클릭 시각 효과 | **켬** | 클릭 시점이 안 보이면 따라 할 수 없다 |
| 시스템 오디오 | 켬 | 알림음·오류음이 리듬을 만든다 |
| 마이크 | **끔** | 합성 음성으로 대체 |

### 녹화 전 화면 준비 (매번 동일하게)

| 항목 | 규정 |
|---|---|
| 에디터·터미널 글꼴 | **평소보다 2~4단계 크게** — 모바일에서 읽혀야 한다 |
| 테마 | **다크 테마 고정** — 채널 시각 정체성 |
| 브라우저 | 새 프로필. 북마크바 숨김, 확장 아이콘 없음 |
| 알림 | 전부 끔 (실수 노출 방지) |
| 개인정보 | 거래처명·금액·이메일은 **녹화 전에 더미 데이터로 교체** |
| 바탕화면 | 아이콘 정리 또는 단색 |

> 💡 **더미 데이터로 바꾸는 과정 자체를 짧게 녹화해 영상에 넣는다.** "개인정보는 이렇게 바꿔뒀습니다" 한 마디가 신뢰를 크게 올린다.

### 녹화 규칙 (타협 불가)

| 규칙 | 이유 |
|---|---|
| **처음부터 끝까지 한 번에 녹화** | 실패 장면이 자연스럽게 남는다 |
| **실패해도 다시 찍지 않는다** | 실패가 콘텐츠다. 다시 찍으면 그 자산이 사라진다 |
| **시작·종료 시각을 메모에 기록** | 실측 수치의 근거. 화면에 시계를 띄워두면 더 좋다 |
| **막힌 순간 소리 내어 말하지 않는다** | 내레이션은 나중에 붙인다. 대신 메모에 시각과 상황을 적는다 |
| **원본 파일 전량 보관** | 정책 소명 시 유일한 증거 |

**녹화 중 작성하는 메모(다음 단계의 입력값이 된다)**
```
00:00 시작
02:14 설치 완료
05:40 첫 결과 — 거래처 열 인식 실패
09:12 원인 파악: 원본 CSV 인코딩 문제
14:30 해결
18:05 완료
수동 작업 소요: 42분 / 도구 작업 소요: 3분 20초
```

## 2. 대본 — AI에 넘기는 입력 구조

대본 품질은 프롬프트의 화려함이 아니라 **입력 재료의 정확도**로 결정된다. 아래 5개를 그대로 준다.

```
[역할] 유튜브 롱폼 내레이션 작성. 시청자는 코드를 못 읽는 실무자.

[구조] 아래 타임코드를 정확히 지킬 것:
0:00-0:20 훅(결과 선공개) / 0:20-0:45 약속 / 0:45-1:10 지도
1:10-5:00 본문1 / 5:00-5:15 재훅 / 5:15-9:30 본문2
9:30-11:30 실패 구간 / 11:30-11:45 재훅 / 11:45-13:30 실측
13:30-14:30 판정 / 14:30-15:00 연결

[재료 1] 녹화 타임라인 메모: (위 메모 그대로 붙여넣기)
[재료 2] 실측 수치: 수동 42분 → 자동 3분 20초, 제작 소요 4시간
[재료 3] 막힌 지점 2곳과 해결 방법: (구체적으로)
[재료 4] 최종 판정: 누가 쓰면 좋고 누가 쓰면 안 되는가
[재료 5] 다음 영상 제목: (연결용)

[문체 규칙]
- 단정형 짧은 문장. 한 문장 25자 이내를 기본으로.
- 과장어 금지: 미쳤다, 충격, 소름, 무조건, 혁명
- 시청자 호칭은 "여러분" 대신 상황을 지목 ("매달 정산하시는 분")
- 마무리는 반드시 "됩니다. 다만 조건이 있습니다."
- 수치는 재료 2에 있는 값만 사용. 없는 숫자를 만들지 말 것.
```

### 대본 인간 검수 (자동화 금지)

| 확인 | |
|---|---|
| 재료에 없는 숫자가 생겼는가 → 삭제 | ☐ |
| 과장 표현이 들어갔는가 → 삭제 | ☐ |
| 판정이 본인의 실제 의견과 같은가 | ☐ |
| 지키지 못할 약속이 없는가 | ☐ |

> **가장 흔한 사고: AI가 그럴듯한 수치를 지어낸다.** "약 70% 단축" 같은 문장이 슬쩍 들어온다. 이건 시청자 기만이자 채널 신뢰의 종말이다. **재료 2에 없는 숫자는 전부 삭제한다.**

## 3. 음성 합성

| 항목 | 값 | 이유 |
|---|---|---|
| 음성 | **1개 선정 후 152일 고정** | 무얼굴 채널에서 목소리가 곧 얼굴 |
| 속도 | 1.05 ~ 1.10배 | 정보 밀도 인상. 1.2배 이상은 피로 |
| 톤 | 차분한 설명조 | 실무자 대상. 흥분한 톤은 신뢰를 깎는다 |
| 문장 간 간격 | 0.3 ~ 0.4초 | 너무 촘촘하면 못 따라온다 |
| 문단 간 간격 | 0.6 ~ 0.8초 | 챕터 전환 신호 |

**합성 전 대본 손질**
- 숫자는 읽는 대로 표기 — `3분 20초` → `삼 분 이십 초`가 자연스러우면 그렇게 표기
- 영문 도구명은 한글 표기 병기 후 발음 확인
- 문장 끝 `~습니다`를 연속 5회 이상 두지 않는다(단조로움)

## 4. 편집 — 3원칙과 실제 파라미터

### 원칙 1. 무음 제거

| 파라미터 | 값 |
|---|---|
| 임계값 | −35 dB |
| 최소 무음 길이 | 0.4초 |
| 앞뒤 여백 유지 | 0.1초 |

여백 0.1초를 남기지 않으면 말이 잘려 부자연스러워진다. **이 값 하나가 체감 품질을 가른다.**

### 원칙 2. 대기 시간 압축

| 대기 상황 | 배속 | 자막 |
|---|---|---|
| 설치·다운로드 | **6배** | `약 4분 소요` |
| 처리·생성 대기 | **4배** | `28초 후` |
| 페이지 로딩 | **8배 또는 컷** | — |
| 결과가 나오는 순간 | **1배** | — |

> ⚠️ **비교 영상(P2)에서는 양쪽 배속을 반드시 동일하게 하고 화면에 명시한다.** 배속이 다르면 비교가 무효이고, 시청자가 알아채면 신뢰가 끝난다.

### 원칙 3. 확대

| 대상 | 배율 | 유지 시간 |
|---|---|---|
| 입력창·명령어 | 1.5 ~ 1.8배 | 입력 끝날 때까지 |
| 오류 메시지 | **2.0배** | 최소 2.5초 (읽을 시간) |
| 결과 표·숫자 | 1.4배 | 3초 |
| 전체 화면 | 1.0배 | 구조를 보여줄 때만 |

**전체 화면을 1배로 오래 두지 않는다.** 1080p 화면을 모바일에서 보면 글자가 안 보이고, 안 보이면 나간다.

### 자막

| 항목 | 값 |
|---|---|
| 위치 | 하단 중앙, 아래에서 12% 지점 |
| 줄 수 | **최대 2줄** |
| 글자 수 | 줄당 최대 20자 |
| 크기 | 1080p 기준 44~52px |
| 스타일 | 흰색 + 검정 외곽선 1.5px 또는 반투명 검정 박스 |
| 강조 | 수치·판정 단어만 강조색 1개 |

## 5. 보조 비주얼 (생성 도구 활용)

| 용도 | 형태 | 분량 제한 |
|---|---|---|
| 구조 설명 | 단순 다이어그램 (박스+화살표) | 편당 1~2장 |
| 전/후 비교 | 좌우 분할 그래픽 | 편당 1장 |
| 수치 강조 | 큰 숫자 카드 | 편당 2~3장 |
| 전환 | 챕터 카드 | 챕터당 1장 |

> ⚠️ **생성한 비주얼이 영상 길이의 절반을 넘지 않게 한다.** 화면 녹화가 주인공이어야 정책상 안전하고, 실제로도 그게 이 채널의 가치다.
> **AI로 생성한 이미지·영상을 사용하면 업로드 시 '변경된 콘텐츠' 공시를 체크한다.**

## 6. 썸네일

| 항목 | 값 |
|---|---|
| 크기 | 1280×720 |
| 안전 영역 | 가장자리 60px 안쪽에 핵심 요소 |
| 레이아웃 | **좌 텍스트(40%) / 우 화면 캡처(60%) 고정** |
| 텍스트 | **최대 7글자, 2줄 이내** |
| 글자 크기 | 최소 170px (1280 기준) |
| 색 | 배경 1색 + 텍스트 1색 + 강조 1색. **3색 초과 금지** |
| 우측 캡처 | 영상 안의 **실제 장면**. 별도 제작 금지 |

### 제작 절차
1. 브랜드 템플릿에서 텍스트·캡처만 교체 → **3안 생성**
2. **120px로 축소해서 확인** — 글자가 안 읽히면 전부 폐기하고 문구를 줄인다
3. 3안 중 1개 선택

### 검증 질문
- 제목과 썸네일이 **같은 말을 반복하지 않는가** (썸네일=결과, 제목=맥락)
- 경쟁 영상 썸네일과 나란히 놓았을 때 구분되는가

## 7. 숏폼 추출

| 항목 | 값 |
|---|---|
| 규격 | 1080×1920 |
| 길이 | 30~50초 |
| 컷 길이 | 최대 4초 |
| 자막 | **필수** (무음 시청 전제) |
| 첫 프레임 | 텍스트가 **반드시** 있어야 함 |

### 세로 재구성 — 단순 크롭 금지

화면 녹화를 9:16으로 그냥 자르면 아무것도 안 보인다. 아래 구조로 재조립한다.

```
┌─────────────────┐
│  텍스트 훅 (상단 20%)  │  ← 큰 글씨 한 줄
├─────────────────┤
│                 │
│  화면 확대 영역 (60%)  │  ← 핵심 부분만 1.8~2.2배 확대
│                 │
├─────────────────┤
│   자막 (하단 20%)     │
└─────────────────┘
```

### 발행 제한
- 같은 템플릿의 숏폼을 **하루 3개 이상 올리지 않는다** (대량생산 신호)
- 숏폼에서 "구독하세요" 직접 요청 금지 → 완주율 하락. **채널명 노출로 대체**

모든 화면·실행·측정 결과는 직접 촬영하고 측정한 원본입니다.

**명명 규칙:** `L{번호}_{짧은주제}_{단계}` — 검색과 정렬이 동시에 된다.

## 10. 품질 게이트 3곳

공정 중 **3곳에서만** 멈춰 선다. 그 외에는 흐름을 끊지 않는다.

| 게이트 | 시점 | 통과 조건 | 실패 시 |
|---|---|---|---|
| **G-A 패키징** | 제작 착수 전 | 09 문서의 5개 기준 통과 | **제작 착수 금지.** 주제 재설계 |
| **G-B 대본** | 음성 합성 전 | 재료에 없는 수치 0개, 과장어 0개 | 대본 수정 |
| **G-C 최종** | 발행 전 | 처음부터 끝까지 재생 + 정책 7항목 | **발행 보류** |

> G-A를 통과 못 한 주제로 제작을 시작하는 것이 가장 큰 낭비다. **클릭되지 않을 영상은 만들 이유가 없다.**

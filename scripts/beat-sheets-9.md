# 나머지 9편 비트시트

완성 대본 3편(#1 P1, #2 P2, #10 P3)이 각 기둥의 **형판**이다. 나머지 9편은 그 형판에 내용을 갈아 끼운다.
아래는 **훅은 그대로 읽을 수 있게 완성**, 나머지는 비트만 잡았다. 훅이 유지율의 40%를 결정하므로 훅만은 초안이 아니라 완성본으로 둔다.

> 각 편의 타임코드 구조는 기둥별 형판을 따른다 — P1은 `S01`, P2는 `S02`, P3는 `S10`.

## #3 · 바이브코딩 3주 하고 알게 된 것 (기대와 달랐던 5가지)
**P2 · 14분 · 썸네일 `3주 해봄`**

**훅 (0:00–0:15)**
> 3주 썼습니다. 결론부터 말씀드리면, 되는 건 확실히 됩니다.
> 그런데 제가 기대했던 것과 다른 게 다섯 가지 있었습니다.
> 특히 네 번째는 시작 전에 알았으면 `[실측: __시간]` 을 아꼈을 겁니다.

**비트**
1. 테스트 조건 — 3주간 뭘 만들었는지, 하루 몇 시간
2. 달랐던 것 1~3 (각 2분): 기대 → 실제 → 왜
3. **재훅**: "네 번째가 제일 컸습니다"
4. 달랐던 것 4~5 — 4번은 가장 아팠던 것, 5번은 의외로 좋았던 것(반전)
5. 실측: 3주간 완성한 것 / 버린 것 개수
6. 판정: 계속 쓸 것인가 — 조건부 예/아니오

**핵심 설계:** 정점 지난 키워드는 **후기 수요로 전환**된다. "써볼까?"가 아니라 "진짜 되나?"를 검색하는 시기. 그래서 소개가 아니라 **검증**으로 간다.

## #4 · 견적서 만드는 도구, 하루 만에 만들기
**P1 · 16분 · 썸네일 `하루면 됨`**

**훅 (0:00–0:20)**
> 거래처 정보만 넣으면 견적서가 이렇게 나옵니다.
> 만드는 데 하루 걸렸습니다. 정확히는 `[실측: __시간]` 입니다.
> 저는 여전히 코드를 못 읽습니다.

**비트**
1. 기존 방식: 매번 이전 견적서 복사 → 수정 → 실수 발생 지점 보여주기
2. 설계 4문장 작성 (S01과 동일 패턴 — **반복이 브랜드**)
3. 생성 → 첫 결과 확인
4. **실패 구간**: 견적서 양식/서식이 깨진 지점. 서식은 AI가 가장 자주 틀리는 영역
5. 실측: 견적서 1건 작성 시간 전/후, 월 건수 × 절감
6. 판정: 견적 건수가 월 `[실측: __]` 건 이하면 손으로 하는 게 낫다

## #5 · AI한테 프로그램 만들라 시킬 때 실패하는 5가지
**P2 · 12분 · 썸네일 `왜 안 되나`**

**훅 (0:00–0:15)**
> 안 되는 이유는 거의 정해져 있습니다. 다섯 가지입니다.
> 저는 이걸 몰라서 첫 달에 `[실측: __시간]` 을 날렸습니다.
> 세 번째가 제일 흔한데, 본인은 절대 모르는 실수입니다.

**비트**
1. 실패 1: 원하는 걸 말로 설명 못 함 → 처방
2. 실패 2: 예시 파일을 안 줌 → 처방
3. **재훅** → 실패 3: "안 돼요"라고만 말함 (오류 메시지 미전달) → 처방
4. 실패 4: 한 번에 너무 많이 시킴 → 처방
5. 실패 5: 결과를 검증하지 않음 → **가장 위험**. 틀린 걸 빠르게 만드는 상태
6. 판정: 다섯 개 중 하나만 고치면 3번

**핵심 설계:** "안 될 때" 질의는 **공급이 항상 부족**하다. 성공담은 넘치고 실패 해법은 없다. 롱테일 수명이 가장 긴 유형.

## #6 · 구글 시트가 매일 보고서를 대신 쓰게 만들었습니다
**P1 · 16분 · 썸네일 `시트가 대신`**

**훅 (0:00–0:20)**
> 매일 아침 이 보고서를 `[실측: __분]` 걸려 만들었습니다.
> 지금은 제가 열기 전에 이미 만들어져 있습니다.
> 구글 시트만 씁니다. 추가로 결제한 것 없습니다.

**비트**
1. 매일 하던 작업 실황 (반복성 강조 — 매일이라는 게 핵심)
2. 설계: 어떤 데이터가 어디서 와서 어디로 가는지 그림 1장
3. 시트 자동화 구축 — 앱스크립트는 **직접 짜지 않고 만들게 시킨다**
4. **실패 구간**: 자동 실행 트리거 시간 설정에서 막힌 지점
5. 실측: 하루 `[실측: __분]` × 근무일 = 월 `[실측: __시간]`
6. 판정: 매일 하는 일에만 쓸 것. 주 1회 작업은 손이 낫다

**전략적 중요도 ★★★** — 유일한 우상향 키워드(+152%)의 대표작. **이 영상이 성과 나면 후속 4편을 즉시 추가한다.**

## #7 · 앱스크립트 한 줄도 못 짜는데 시트 자동화한 방법
**P3 · 11분 · 썸네일 `한 줄도 못 짬`**

**훅 (0:00–0:15)**
> 앱스크립트, 저는 한 줄도 못 짭니다. 지금도 못 짭니다.
> 그런데 이 시트는 자동으로 돕니다.
> 방법은 세 단계고, 붙여넣을 문장도 그대로 드리겠습니다.

**비트**
1. 3단계 구조 제시 (템플릿 기둥이므로 구조를 먼저 공개)
2. 단계별 실행 — 각 단계마다 복붙할 문장을 화면에 3초 고정
3. 흔한 실수 2가지
4. 실측 + 판정
5. **배포**: 문장 전체를 설명란·고정 댓글에 무료 공개

## #8 · 문의 들어오면 시트가 알아서 정리하게 만들기
**P1 · 15분 · 썸네일 `알아서 정리`**

**훅 (0:00–0:20)**
> 문의가 들어오면 여기 자동으로 쌓입니다. 분류까지 돼 있습니다.
> 제가 손대는 건 답장뿐입니다.
> `[실측: __일]` 동안 `[실측: __건]` 처리했고, 놓친 건 `[실측: __건]` 입니다.

**비트**
1. 기존: 메일함에서 놓치는 문의 → 실제 손실 사례
2. 설계 → 구축
3. **실패 구간**: 분류가 틀린 케이스. **틀린 분류를 그대로 보여주는 것이 핵심** — 완벽한 척하면 신뢰가 깨진다
4. 실측: 놓친 건수 전/후
5. 판정: 문의량이 일 `[실측: __]` 건 이하면 불필요

**설계 노트:** #6·#7·#8이 **하나의 클러스터**를 이룬다. 서로 최종화면으로 연결하고 같은 재생목록에 넣는다 → 세션 시청 연장.

## #9 · 구글 시트 자동화 3개월 후기 — 뭐가 깨졌나
**P2 · 12분 · 썸네일 `3개월 후`**

**훅 (0:00–0:15)**
> 3개월 돌렸습니다. 두 개는 아직 잘 돌고, 하나는 껐습니다.
> 끈 이유가 제일 중요합니다.
> 자동화가 실패하는 건 만들 때가 아니라 **만들고 나서**입니다.

**비트**
1. 3개월 전 만든 것 3개 복기
2. 살아남은 2개 — 왜 살아남았나 (공통점)
3. **재훅** → 끈 1개 — 왜 껐나
4. 유지 비용이라는 개념: 자동화도 관리가 필요하다
5. 판정: 만들기 전에 "이걸 6개월 관리할 것인가"를 물어라

**설계 노트:** 시리즈 완결편. **재방문 시청자를 만드는 유형**이며, "후기" 검색 수요를 흡수한다.

## #11 · 매크로 vs AI — 스톱워치로 실측했습니다
**P2 · 13분 · 썸네일 `수동 vs AI`**

**훅 (0:00–0:15)**
> 같은 작업을 매크로로 한 번, AI로 한 번 했습니다. 스톱워치로 쟀습니다.
> 결과가 제 예상과 반대였습니다.
> 그리고 속도보다 중요한 게 따로 있었습니다.

**비트**
1. 테스트 조건 공개 (양쪽 동일 조건 명시)
2. 만드는 시간 비교
3. **실행 시간 비교** — 여기서 예상과 반대 결과
4. **재훅** → 세 번째 축: 고장 났을 때 고치는 시간
5. 판정: 작업 빈도와 변화 빈도로 나뉜다 — 2×2 표

**핵심 설계:** "매크로"는 죽어가는 키워드(−84%). 그 검색자를 **살아있는 쪽으로 옮기는 다리** 역할. 사양 키워드는 버리는 게 아니라 **통로로 쓴다.**

## #12 · 영수증 사진 → 정산표 자동 완성
**P1 · 17분 · 썸네일 `사진 한 장`**

**훅 (0:00–0:20)**
> 영수증 사진을 찍어서 넣으면, 여기까지 자동으로 채워집니다.
> `[실측: __장]` 넣어봤고, 틀린 건 `[실측: __장]` 이었습니다.
> 틀린 것들에 공통점이 있었습니다.

**비트**
1. 기존: 영수증 쌓아두고 월말에 몰아서 입력하는 실황
2. 설계 → 구축
3. **실패 구간**: 인식 실패한 영수증들. **실패한 것들을 나란히 놓고 공통점 분석** — 이 채널에서 가장 강한 장면
4. 실측: 장당 입력 시간, 정확도
5. 판정: 정확도 `[실측: __%]` 이면 **검산은 여전히 사람이 해야 한다**. 자동화가 검산까지 없애주지 않는다

**설계 노트:** **숏폼 소재로 최상.** "사진 넣으니 표가 채워진다"는 시각적 임팩트가 커서 결과 컷 하나로 숏폼이 성립한다. 이 편에서만 숏폼 5개를 뽑는다.
